## Описание

SuperTutor — учебный многостраничный сайт каталога курсов и репетиторов. Проект основан на HTML/CSS-сайте из контрольной работы №1 (`kr1-html-css-shop`): сохранены страницы, тексты, изображения и BEM-классы. В КР №3 сайт сделан адаптивным (телефон, планшет, ПК) и доступным.

**Bootstrap и другие CSS-фреймворки не используются.** Вся адаптивность написана вручную: медиазапросы, Flexbox, CSS Grid, responsive images.

## Адаптивные решения

- Создан отдельный файл `css/responsive.css`, подключён на всех страницах **после** `style.css`, чтобы переопределять базовые правила.
- На всех страницах есть `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.
- Подход **Mobile First**: базовые стили в `responsive.css` рассчитаны на телефон, на больших экранах правила расширяются через `@media (min-width: ...)`.
- Контрольные точки:

| Ширина | Что меняется |
| --- | --- |
| до 520px | одна колонка карточек, меню свёрнуто в кнопку «Меню», таблица характеристик в виде карточек |
| от 520px | каталог: сетка `repeat(auto-fill, minmax(220px, 1fr))` |
| от 640px | таблица характеристик возвращается к табличному виду |
| от 700px | главная: три карточки курсов в ряд |
| от 768px | меню в строку, липкая шапка, форма заявки в две колонки |
| от 900px | hero и страница курса в две колонки |
| от 1024px | каталог: боковой фильтр слева, липкий при прокрутке |

- **Навигация** (Flexbox): на телефоне пункты в колонку под кнопкой «Меню», на планшете и ПК в строку. Липкая шапка включается только от 768px.
- **Hero-блок** (Grid): на мобильном одна колонка, от 900px две. Заголовки масштабируются через `clamp()`.
- **Сетка карточек** (Grid): `minmax(0, 1fr)` и `overflow-wrap: anywhere` не дают длинному тексту ломать карточки. Список преимуществ использует `repeat(auto-fit, minmax(...))` без медиазапросов.
- **Каталог**: фильтр над списком, на мобильном свёрнут в `<details>`, на ПК раскрыт и закреплён слева (`position: sticky`).
- **Форма заявки**: поля в одну колонку, на планшете парами в две колонки (Grid); высота полей не меньше 44px, размер шрифта 16px (iOS не увеличивает страницу при фокусе); кнопки на мобильном друг под другом.
- **Таблица характеристик**: обёрнута в `.table-wrapper` (при нехватке места прокручивается только она), на узком экране превращается в «карточки» «параметр — значение».
- **Модальное окно** (`<dialog>`): ширина `min(100% - 32px, 560px)`, высота ограничена высотой экрана, содержимое прокручивается.
- **Плавающая кнопка** на мобильном растянута по ширине экрана, у подвала добавлен запас, чтобы кнопка не закрывала текст.

## Responsive images

- Базовое правило `img { max-width: 100%; height: auto; }`.
- Карточки курсов: `<picture>` с источником WebP и запасным JPEG, у каждого — `srcset` с шириной 320/480/720 px и `sizes`, подходящие под сетку. У `<img>` заданы `width` и `height`, чтобы страница не «прыгала», у картинок ниже первого экрана — `loading="lazy"`.
- Hero-блок: `<picture>` с **разными кадрами** (`art direction`) для телефона (16:9, 480px), планшета (16:9, 736px) и ПК (квадрат, 560px), в формате WebP с запасным JPEG.
- Страница курса: `srcset` и `sizes` для основной картинки.
- Варианты изображений сделаны из исходных файлов КР №1 (обрезка до 4:3 и сжатие).

## Доступность (a11y)

- Добавлена ссылка пропуска «Перейти к основному содержимому» (`skip-link`), видимая при фокусе с клавиатуры.
- Основной контент в `<main id="main">`, навигация в `<nav aria-label>`, единая навигация на всех страницах, текущая страница отмечена `aria-current="page"` (и линией, не только цветом).
- Видимый фокус: единое жёлтое кольцо `:focus-visible` для ссылок, кнопок, полей, `summary`.
- Исправлена контрастность: светлый зелёный `--color-primary`, тёмный текст на кнопках, светлый `--color-muted` (раньше `#666` на тёмном фоне), цвет ошибок; ссылки в карточке контактов. Проверено расчётом по формуле WCAG: весь текст не ниже 4.5:1 (крупный не ниже 3:1).
- У всех полей форм есть `<label for>`; подсказка о формате телефона связана через `aria-describedby`.
- Ошибки форм: текст под полем, `aria-invalid`, связь через `aria-describedby`, значок ⚠ (не только цвет), фокус переходит на первое поле с ошибкой. Сообщение об успехе в `role="status"`.
- У всех изображений осмысленный `alt`; шапка таблицы с `scope`, первый столбец — `<th scope="row">`.
- Модальное окно на `<dialog>` с `aria-labelledby`: фокус внутри окна, закрытие по Escape и по клику вне окна.
- Кнопка меню: `aria-expanded` и `aria-controls`, Escape закрывает меню.
- Области нажатия (кнопки, пункты меню, поля, `summary`) не меньше 44px по высоте.
- Для пользователей с `prefers-reduced-motion` плавная прокрутка отключена.
- Исправлены ошибки КР №1: разный набор пунктов меню на страницах (теперь одинаковый), отсутствовавшие пробелы в тексте, разделители в хлебных крошках, название товара в скрытом поле заявки.

## Самостоятельные доработки

- Меню: кнопка «Меню» с `aria-expanded`, закрытие по Escape и по клику на пункт, возврат фокуса на кнопку.
- Каталог: боковой фильтр сворачивается в `<details>` на мобильном и раскрывается на ПК.
- Таблица характеристик адаптирована не только прокруткой, но и карточным представлением.
- Несколько вариантов responsive images: WebP + JPEG, `srcset`/`sizes`, `picture` с разными кадрами для hero.
- Расширенная доступность: skip-link, видимый фокус, ARIA там, где нужно, доступные сообщения об ошибках, исправленный контраст, доступное модальное окно.
- Дополнительная форма обратной связи на странице контактов.
- Публикация через GitHub Pages (ссылка выше).

## Как проверить

1. Открыть `index.html` в браузере (сервер не нужен).
2. Открыть DevTools (F12) → режим устройства (Ctrl+Shift+M) и проверить ширины 360, 430, 768, 1024 и 1440 px.
3. На телефонной ширине раскрыть меню кнопкой «Меню»; в каталоге раскрыть «Фильтры».
4. На странице курса проверить таблицу: на узком экране «карточки», от 640px обычная таблица.
5. Нажать Tab: первой в фокус попадает ссылка пропуска; пройти по странице клавиатурой.
6. Отправить пустую форму на `order.html` или в окне «Заказать» и посмотреть сообщения об ошибках.
7. Запустить Lighthouse (DevTools → Lighthouse → Accessibility).
